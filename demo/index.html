WebGPU · zero dependencies

glaze.

GPU effects over the DOM you already have. Point it at an image, get a shader. If anything fails — no WebGPU, a dead device, reduced motion — the page keeps its images. Safari only enabled WebGPU by default in 26.0; plenty of real visitors still have none of it, and none of them should see a hole. 

// that's the whole API
glaze('#hero img', { effect: 'displace' });
01 — displace

Warps with the scroll, and only with the scroll

A still page is an untouched image. The displacement is driven by scroll velocity, so the effect costs nothing when nothing is happening — and the warp is weighted towards the edges, so the subject stays legible while the frame moves.

Which makes it hard to look at: by the time you have focused on the image you have stopped scrolling, and the effect is gone. Hold it open instead — this is the velocity option, the same one you need if you drive the page with Lenis or ScrollSmoother.

02 — reveal

An edge that tears instead of fading

Opacity fades read as a loading state. This is a directional mask with a noisy leading edge driven by scroll progress: the image arrives as material rather than as a CSS transition.

03 — rgb

Chromatic split, kept honest

The split is vertical because scrolling is vertical — splitting on the other axis is the mistake that makes this effect look pasted on. Past about 0.5 strength it stops reading as optics and starts reading as a broken screen, so the default is well under that. It also needs an image with colours to separate — on a near-monochrome photograph this effect does almost nothing, which is a property of the image and not of the shader.

04 — the part that matters

It never removes your content

Each image is hidden only after its texture has decoded and uploaded, and it is put back exactly as it was found on destroy(). Turn off WebGPU in your browser flags and reload: the page looks like an ordinary page, because it is one.
